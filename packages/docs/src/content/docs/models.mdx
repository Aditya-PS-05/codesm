title: Models
description: Discover, select, and configure current coding models.
---

Codesm accepts exact `provider/model-id` strings. The picker is a convenience;
a new model does not need a codesm release before you can use its ID.

## List and refresh models

```bash
codesm models
codesm models --provider kimi
codesm models --refresh --provider openai
codesm models --refresh --provider openrouter --json
```

Without `--refresh`, the command uses built-in examples and your configured model
IDs. Refresh queries connected providers and OpenRouter's public catalog. Failures
are reported per provider and retain its offline entries; the CLI exits with code
1 if any requested refresh fails. JSON output contains `models` and `errors`.
A refreshed list comes from the provider but does not grant account access.

In the TUI, `/models` displays the same catalog and refreshes it in the background.
Press `ctrl+r` to refresh again. Search by name or exact ID, or type a full
`provider/model-id` and select it even if it is not listed. `/connect` saves the
selected provider's API key.

## Select a model

```bash
codesm run --model openai/gpt-5.6-luna
codesm run --model anthropic/claude-sonnet-5
codesm run --model kimi/kimi-k3
codesm run --model zai/glm-5.3
codesm chat "Explain this project" --model google/gemini-3.8-flash
```

Recognized bare model prefixes also work, such as `gpt-6-astra`, `kimi-k3`,
`glm-5.3`, and `claude-fable-5-1`. Use a provider prefix when choosing a gateway or
custom deployment. `openrouter/anthropic/claude-fable-5.1` is an OpenRouter model
ID; `anthropic/claude-fable-5-1` is the direct Anthropic ID.

For a project default:

```json title="codesm.json"
{
  "model": "openai/gpt-5.6-terra"
}
```

The CLI `--model` option overrides the default. Existing explicit models and
saved preferences remain usable. New installations default to Claude Sonnet 5.

## Specialist models and output allowances

```json title="codesm.json"
{
  "model": "openai/gpt-5.6-luna",
  "agents": {
    "main": {"reasoning_effort": "low", "max_output_tokens": 8192},
    "planner": {"model": "anthropic/claude-sonnet-5"},
    "oracle": {"model": "openai/gpt-6-astra", "reasoning_effort": "high"},
    "coder": {"model": "kimi/kimi-k3", "reasoning_effort": "low", "max_output_tokens": 16384}
  }
}
```

Configure the credentials and account access needed by each selected provider.
Output tokens include reasoning for reasoning models, so a low allowance can
end before the answer. `context_tokens` defaults to 128,000; set it explicitly if
you want a different context budget. Role settings and shared request/token/dollar
limits are described in [Config](/config). Unknown model prices stay unknown;
add current `model_prices` before enforcing a dollar budget.

Rush mode selects a faster model within the current provider when a mapping is
available. Custom providers with no rush mapping keep the selected model.

## Custom deployments

Add an OpenAI-compatible endpoint and optional picker entries:

```json title="codesm.json"
{
  "providers": {
    "local-server": {
      "base_url": "http://localhost:8000/v1",
      "api_key": "not-needed",
      "models": ["my-local-coder"]
    }
  }
}
```

`codesm run --model local-server/my-local-coder` now uses that endpoint. A server
that implements `/models` can be queried with
`codesm models --refresh --provider local-server`.

See [Providers](/providers) for the verified model examples, API-key variables,
endpoint overrides, and links to official catalogs.
