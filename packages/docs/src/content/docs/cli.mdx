## Start a session

```bash
codesm run
codesm run /path/to/project --model openai/gpt-5.6-luna
codesm run --session SESSION_ID
```

Bare `codesm` displays help. The `run` command starts the interactive TUI.
Use `/connect` to save provider credentials and `/models` to choose a model.

## Work in the terminal

The UI uses one compact, full-width transcript without a sidebar. The prompt stays
at the bottom, with the current model and estimated context remaining in the footer.
Tool output is collapsed by default; commands, file paths, and completion or failure
status remain visible.

| Key | Action |
|-----|--------|
| `Ctrl+T` | Expand or collapse full tool output, reasoning summaries, and specialist details |
| `Esc` | Interrupt active work |
| `Enter` | Send a message, or queue it while work is running |
| `Tab` | Queue a message during active work; switch Smart/Rush mode while idle |
| `Ctrl+P` | Open the command palette |

Use `/mode` to choose Smart or Rush mode, `/theme` to select a color palette, and
`/cost` to inspect usage and cost. **Terminal** is the default palette. Model and
theme selection remain available through their slash commands; `Ctrl+T` controls
transcript details.

## Send one prompt

```bash
codesm chat "Explain src/main.py" --dir ./project
codesm chat "Find the failing test" --model kimi/kimi-k3
```

`chat` streams plain text and task status to the terminal. It accepts the same
`provider/model-id` format as `run` and `debug`.

## Discover models

```bash
codesm models
codesm models --provider zai
codesm models --refresh --provider openai
codesm models --refresh --provider openrouter --json
```

Use `--dir ./project` to load that project's configuration. Built-in and configured
models work offline; `--refresh` queries provider catalogs and reports per-provider
failures. See [Models](/models) and [Providers](/providers) for model IDs,
credentials, custom endpoints, and exact-ID selection.

## Command help

```bash
codesm --help
codesm --version
codesm run --help
codesm debug --help
codesm eval --help
codesm memory --help
codesm index --help
codesm mcp --help
```

Model preferences and execution limits are configured in `codesm.json`, or in the
file named by `CODESM_CONFIG`. [Config](/config) describes configuration precedence.

## Debug a failure

```bash
codesm debug "Fix the failing checkout tests" --dir ./project
```

In the terminal UI, use `/debug <problem>`. Codesm records a failing reproduction
command and its working directory, hypotheses, command output, and verification.
`debug(action="verify")` reruns the original command; a different passing command
cannot verify the recorded failure. There are at most three verification attempts
and one consultation through `debug(action="consult", reason="...")`.

The run finishes as `verified` only after a passing rerun. Missing reproduction,
unavailable checks, or exhausted attempts leave it `unverified`. A later mutation
invalidates a prior verification. `/debug off` ends this workflow. Evidence is
saved with the session. Ordinary tool approval rules still apply; an operation
requiring interactive approval is denied in headless use rather than hanging.

## Compare execution modes

```bash
codesm eval benchmarks/fix-bug-with-tests.yaml \
  --model openai/gpt-5-mini \
  --variants single,specialists,adaptive --repeat 3 \
  --pretty --output comparison.json
```

Each run uses a fresh temporary workspace. An optional `directory` in the YAML or
`--dir` supplies a fixture to copy; relative fixture paths resolve against the YAML
file. Setup and assertion hooks must use workspace-relative paths. Hooks are
trusted shell code, so a fresh copy is not an OS sandbox. Existing checkout Git
metadata, dependency directories, and caches are excluded from copies. MCP is only
loaded from the fixture's `mcp-servers.json`, not the caller's global configuration.

Reports include pass rate, completion state, child usage, tool failures, estimated
and unpriced requests, p50/p95 latency, and all-run cost per successful result.
Percentiles from small samples are descriptive, not performance claims. Manual
corrections are reported as unknown because the runner does not measure them.
