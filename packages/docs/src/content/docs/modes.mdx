The terminal has two model modes. They change the selected model; tool permissions
and specialist roles are configured separately.

## Overview

| Mode | Model selection | Typical use |
|------|-----------------|-------------|
| **Smart** | Your selected base model | Complex tasks, debugging, architecture |
| **Rush** | The provider's fast-model choice, when available | Simple edits and quick fixes |

If a provider has no Rush model, Codesm keeps the base model. The footer always
shows the effective model. Actual cost and speed depend on the model, provider,
and task; switching modes does not guarantee a fixed saving.

## Switching modes

Press **Tab** while idle, or use the mode selector:

```txt frame="none"
/mode
```

You can select either mode directly:

```txt frame="none"
/smart
/rush
```

While work is active, **Tab** queues the text in the composer for the next turn.
It does not switch modes during that task.

Smart is the initial default. Codesm remembers your last mode selection for future
sessions. Selecting a new base model with `/models` returns to Smart mode.

## Choosing the base model

Choose a model when launching:

```bash
codesm run --model openai/gpt-5.6-luna
```

Or set the project default:

```json title="codesm.json"
{
  "model": "openai/gpt-5.6-luna"
}
```

Rush choices come from the provider catalog. The terminal does not read `mode` or
`modes` objects from `codesm.json`; use `/mode` for the saved UI preference.

## When to use each mode

Use Smart for ambiguous tasks, multi-file changes, difficult debugging, or reviews
that need the model you selected. Try Rush for small edits and well-defined tasks,
and inspect the result before choosing it for more complex work.

Use `/cost` to inspect actual session usage. Compare repeated evaluations on your
own tasks when assessing speed and cost; see [CLI](/cli#compare-execution-modes).

## Specialist models

Specialists can use different models through role profiles:

```json title="codesm.json"
{
  "agents": {
    "finder": { "model": "google/gemini-3.8-flash" },
    "oracle": { "model": "openai/gpt-5.6-sol" }
  }
}
```

An explicit role model or routed model can override the parent model. Without an
override, a specialist inherits the parent model. Set `pin_model: true` to keep
all calls on the parent model. The runtime does not use `subagent_modes` or
`inherit_mode` settings. See [Config](/config) for profiles and routing.

## Planning and permissions

Smart and Rush do not switch between Build and Plan agents. Request the `planner`
specialist for a plan, or set `read_only: true` to restrict the entire task to
read-only tools. See [Agents](/agents) for role capabilities.
