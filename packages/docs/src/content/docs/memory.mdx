---
title: Local Memory and Model Continuity
description: Continue work across providers, sessions, and restarts using local history.
---

codesm keeps a full local transcript and a smaller working context. Switching from
OpenAI to Anthropic, OpenRouter, or another provider keeps the same session,
completed tool calls, results, and task list. It does not ask the old provider to
prepare a handoff.

## Continue after a provider limit

1. Open `/models` and choose another connected provider's model.
2. Send `continue`, or describe the next step.

If work is still running, interrupt it first. To resume after restarting codesm:

```bash
codesm run /path/to/project --session SESSION_ID --model anthropic/YOUR_MODEL_ID
```

Use `/session` to select a saved session. The saved project directory is used when
resuming a session. Provider limits and codesm's own configured request, token, or
cost limits are separate; changing models does not reset the latter.

## What survives

- User messages and assistant responses, including partial responses when a
  request fails or is interrupted.
- Tool arguments and returned output, including edits, test output, errors, and
  executed commands.
- Specialist results, task lists, debugging state, usage, and execution events.
- Compacted working context, alongside the complete original transcript.
- Known file paths and their size/mtime at the last read or edit. On continuation,
  codesm checks metadata for recent known files and marks changes for verification.
- Parent-session links, task lists, and known file state when forking or handing off.

A running response is checkpointed on its first text chunk and at most once per
second thereafter. Normal failure and cancellation save the remaining partial
text. A hard process kill or power loss can lose the text since the last checkpoint;
work that was in flight is marked interrupted, not successful. Unknown tool outcomes
must be checked before retrying an action.

Memory preserves the output codesm actually received; it cannot recover tool output
that a tool discarded before returning, or a provider's hidden internal reasoning.
Opaque provider replay data stays local and is used only by the compatible provider.

## How the next model uses memory

Every turn receives the session's working conversation plus a bounded continuation
brief: previous run status, tasks, specialist results, known file state, saved notes,
and related history excerpts. Compaction checkpoints are reused after a model switch
or restart; full historical output remains searchable.

The `recall` tool searches local history and reads complete records in pages. It
needs no model call, embeddings, network service, or extra dependency. Search is
limited to the exact project directory, across that project's sessions. Retrieved
text is historical evidence; current instructions take precedence.

This avoids repeating investigation solely to rebuild lost context. It does not
guarantee that a model never rereads files: external edits, an uncertain action, or
missing evidence can require fresh checks. Size/mtime checks are hints, not content
hashes or proof that a test result still applies.

## Inspect local history

```bash
# Search conversations, tool arguments/results, and execution logs
codesm memory search "token refresh"
codesm memory search "pytest" --session SESSION_ID
codesm memory search "auth.py" --directory /path/to/project

# Read a returned record ID; follow next_offset for more of a large record
codesm memory read 42
codesm memory read 42 --offset 12000

# Refresh the index from saved session JSON and event logs
codesm memory reindex
```

Existing sessions and execution logs are imported once for each project. Indexing
reads codesm's saved records; it does not crawl the repository. `reindex` can import
records created by an older codesm process after the initial migration.

## Add persistent notes

```bash
codesm memory add "Use pytest for this project" --type preference
codesm memory add "Prefer concise explanations" --type preference --global
codesm memory list
codesm memory forget MEMORY_ID
codesm memory clear --project
```

Notes are loaded into the continuation brief automatically. `memory clear` and
`memory forget` manage these explicit notes; they do not erase session history.
Delete a saved session to remove its transcript, todos, execution log, and indexed
records. No automatic retention expiry is applied to saved history.

## Local storage

```text
~/.local/share/codesm/
├── session/<session-id>.json       # Complete transcript and working checkpoint
├── todo/<session-id>.json          # Task list
├── events/<session-id>.jsonl       # Execution events, including nested tools
└── memory/
    ├── history.sqlite3            # Project-scoped SQLite full-text index
    ├── global/items.json          # Explicit global notes
    └── project/<project-id>/items.json
```

Set `CODESM_DATA_DIR` to use a different local storage directory. Session writes
are atomic; the history index uses SQLite transactions. If indexing fails, the
session JSON remains available for recovery and reindexing.

Stored text can contain private code or secrets printed by tools. The archive is
local and unencrypted. Indexing does not upload it; relevant excerpts and working
history are sent to the provider you choose as part of its model context. Local
history covers codesm activity, not unrelated terminal sessions or system logs.
