title: Providers
description: Connect current coding models from OpenAI, Anthropic, Kimi, GLM, and other providers.
---

Use `codesm run --model provider/model-id` with a provider API key, or open
`/connect` in the TUI. Each provider uses its own credential; an OpenAI key is not
used for Kimi, GLM, or another service.

## Built-in providers

These coding/chat model examples were checked against official catalogs on
September 5, 2026. Model access depends on your account and endpoint. Use
`codesm models --refresh --provider openai` (or another provider) for the current
catalog. The built-in list is a starting point, not an allowlist.

A model appearing in a catalog does not guarantee your key has access. For example,
GPT-6 Astra is initially rolling out through OpenAI's Trusted Access Program.
[OpenAI's current model guidance](https://developers.openai.com/api/docs/guides/latest-model)
describes its rollout and supported request parameters.

## Examples

```bash
export MOONSHOT_API_KEY="your-key"
codesm run --model kimi/kimi-k3
```

```bash
export ZAI_API_KEY="your-key"
codesm debug "Reproduce and fix the failing test" --model zai/glm-5.3
```

```bash
export OPENROUTER_API_KEY="your-key"
codesm run --model openrouter/moonshotai/kimi-k3
codesm models --refresh --provider openrouter
```

OpenRouter discovery filters for tool support and excludes batch-only variants.
It also provides access to other families, including Qwen, MiniMax, and Llama,
without a separate codesm integration. Copy the exact ID from `codesm models`.

## Endpoint overrides and coding plans

Z.ai's Coding Plan uses a different endpoint from its standard API:

```json title="codesm.json"
{
  "model": "zai/glm-5.3",
  "providers": {
    "zai": {
      "base_url": "https://api.z.ai/api/coding/paas/v4",
      "api_key_env": "ZAI_API_KEY",
      "options": {
        "extra_body": {"thinking": {"type": "enabled", "clear_thinking": false}}
      }
    }
  }
}
```

See the [Z.ai endpoint guide](https://docs.z.ai/api-reference/introduction) and
[preserved thinking documentation](https://docs.z.ai/guides/capabilities/thinking-mode).
If an endpoint does not expose a models API, enter its model ID directly or add it
to `providers.zai.models`.

## Other OpenAI-compatible endpoints

No plugin is required for an additional compatible provider:

```json title="codesm.json"
{
  "model": "company/my-coding-model",
  "providers": {
    "company": {
      "base_url": "https://your-endpoint.example/v1",
      "api_key_env": "COMPANY_API_KEY",
      "models": ["my-coding-model"]
    }
  }
}
```

Then run `codesm run` or `codesm run --model company/another-model`.
Compatible endpoints use Chat Completions by default. A compatible Responses
endpoint can opt into `options.api: "responses"`. Azure's distinct deployment and
API-version authentication scheme is not automatically configured by this option.

## Reasoning and tool history

Codesm retains native OpenAI response items, Anthropic thinking signatures, Kimi/
GLM/DeepSeek reasoning content, Gemini tool signatures, OpenRouter reasoning
metadata, and Mistral thinking blocks across tool calls. These fields are scoped
to their originating provider and model. Thinking is never printed as the answer.

Keep reasoning effort unset to use a provider's default, or select a supported
value in the [role profile](/config). The accepted values differ by model; for
example, Kimi K3 accepts `low`, `high`, or `max`, whereas Mistral's current reasoning
models accept `high` or `none`. Codesm does not silently increase output budgets.
